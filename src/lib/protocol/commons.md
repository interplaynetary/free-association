# Commons: Infrastructure for Communal Production

## The Problem with Outputs

**In capitalism, production is recognized as social only after the fact** - through market exchange:

```
Individual labor → Private output → Exchange value → Market reveals social character
```

Each person produces independently, creates something they own, then exchange proves (or doesn't) whether their labor was socially necessary.

**The output** is the problem. It's the medium that:
- Enforces producer/consumer separation
- Requires exchange for social recognition
- Makes coordination dependent on ownership

**In Soviet planning, the output remains:**

```
Individual labor → State output → Bureaucratic allocation → Plan reveals social character
```

Different coordination mechanism, same fundamental structure. Labor still produces discrete outputs, just distributed by plan instead of price.

**Both systems** treat production as individuals making things, then coordinating after. The "output" is where private labor becomes social labor - through exchange or through plan.

## What Commons Change

**Commons presuppose the communal character of production from the outset.**

There are no outputs. There are only **slots** (what's needed) and **fills** (contributions).

```
Communal need → Slot describes requirement → Contribution fills slot → Composition progresses
```

**Your labor doesn't produce "a thing" you own.** It fills a slot in a communal process. The social character of your labor isn't revealed post-hoc through exchange or allocation - it's **presupposed** in the slot structure itself.

## Communal Infrastructure as Example

### **Traditional Model: Outputs All The Way Down**

Building community broadband:
```
Company A makes routers → sells to Company B
Company B installs equipment → sells service to residents  
Residents pay monthly → receive internet access

(Each arrow is an exchange of outputs for money)
```

**Problem:** The infrastructure is social (we all need connectivity), but it's built through private outputs and exchange. Coordination happens through markets, which means:
- Profit extraction at every boundary
- Ownership determines access
- Social need mediated by private property

### **Soviet Alternative: Planned Outputs**

```
State allocates routers → State installs equipment → State provides service

(Each arrow is bureaucratic allocation of outputs)
```

**Problem:** Still treating production as creating discrete outputs, just coordinated by plan instead of price. The infrastructure is more accessible, but the underlying structure (output-based coordination) remains.

### **Commons Model: No Outputs, Only Composition**

```
Commons: "Community Broadband Network"
  Slot: Network design [needs: technical specs]
  Slot: Equipment procurement [needs: routers, fiber, etc.]
  Slot: Installation labor [needs: crew coordination]  
  Slot: Ongoing maintenance [needs: tech support rotation]
  Slot: Community governance [needs: decision process]
```

**No one "owns" the routers.** No one "sells" installation. No one "produces internet access as a commodity."

Instead:
- Slots describe what the community needs
- People contribute to fill slots
- The composition completes as slots fill
- The infrastructure exists as a communal accomplishment

**The social character of production is presupposed** - the commons template itself declares "this is communal infrastructure" and the slots structure communal participation.

## Coordination Patterns as Commons

### **The Traditional Tragedy**

Every community group trying to build shared infrastructure must:
- Figure out governance from scratch
- Rediscover effective coordination patterns
- Pay consultants for "best practices"
- Keep their solutions private (competitive advantage)

**Why?** Because coordination knowledge is treated as proprietary. Each org hoards what works.

### **Commons as Commons Infrastructure**

```typescript
// Someone figures out good community broadband governance:
const commonsTemplate = {
  name: "Community Broadband Network",
  slots: [...]
}

// Content-addressed ID computed from structure:
const id = sha256(commonsTemplate) // → "a3f8c9d2..."

// Now ANYONE can reference it:
"We're using commons a3f8c9d2 for our network"
```

**What this means:**

1. **Convergent discovery:** If another community designs the same structure, they get the same ID
2. **Zero-cost replication:** Just reference the commons template, don't reinvent it
3. **Collective improvement:** Fork the template, improve it, new hash emerges
4. **Citeable patterns:** "Commons a3f8c9d2 has been used successfully by 50 communities"

**The coordination pattern itself becomes a public good.**

Not "our secret sauce for building networks" but "the hash of effective community broadband coordination is a3f8c9d2, and here's what we learned implementing it."

## From Exchange to Participation

Instead of your participation in social production being mediated by **exchange of outputs you own**, it is mediated by **the communal structure of production itself**

### **Commons Implementation**

**You don't exchange outputs. You fill slots.**

Your labor is social from the outset because:
- The slot exists within a communal template
- The template's social character is presupposed (it's public, content-addressed)
- Filling the slot is direct participation in communal production
- No exchange required to prove your labor was socially necessary

**The commons template IS the "social conditions of production within which the individual is active."**

## Two Commons, One System

**1. Coordination Patterns as Commons**
- Templates are content-addressed → mathematically determined IDs
- Same pattern = same hash = universal citation
- Can't be owned, only discovered/improved/forked
- Accumulates collective knowledge about "how to coordinate"

**2. Production as Communal**
- No outputs to own/exchange
- Slots describe communal needs
- Contributions fill slots directly
- Social character presupposed, not market-revealed

**These reinforce each other:**

Because templates are commons → patterns spread freely → more communal production becomes possible

Because production is communal → better patterns emerge → commons enriches

## What Gets Built

Not: "Everyone gets their own internet"  
But: "We build a communal network through coordinated contribution"

Not: "Company X owns the coordination pattern for broadband deployment"  
But: "Commons a3f8c9d2 describes effective community broadband, anyone can use it"

Not: "Exchange of outputs mediates participation"  
But: "Slot structure mediates participation"

**Infrastructure that is:**
- **Communal in production** (no outputs, only composition)
- **Commons in coordination** (patterns are public goods)
- **Participatory in governance** (who fills slots is governed, not exchanged)

## The Core Insight

**You can't have communal production coordinated by proprietary patterns.**

If "how to build community broadband" is trade secret → production remains capitalist (profit at coordination boundary)

If "how to build community broadband" is public but each instance creates owned outputs → production remains capitalist (profit at output boundary)

**Commons make both communal:**
- Patterns are mathematical objects (commons)
- Production has no outputs (communal)

This is **post-output, commons-based coordination infrastructure.**

The social character of labor presupposed. The means of coordination freely available. Participation mediated by communal structure, not exchange.

---

**That's the system:** Slots instead of outputs. Templates instead of trade secrets. Composition instead of exchange. Commons all the way down.
