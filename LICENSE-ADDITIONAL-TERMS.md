## 1. Attribution Requirement (Section 7b)

Any use of this software, including modified versions and network services, 
must display prominent attribution visible to end users:

**"Powered by Free Association coordination infrastructure  
https://github.com/interplaynetary/free-association"**

This attribution requirement applies to:
- Web interfaces (displayed in footer or about page)
- API services (included in API documentation and responses)
- Command-line tools (displayed in help text or version info)
- Desktop/mobile applications (displayed in about/credits section)

**Rationale:** This preserves credit to the project and prevents invisible 
cooptation while allowing full freedom to use and modify the software.

## 2. Protocol Fidelity Notice (Section 7c)

Modified versions that alter the core coordination algorithm (recognition 
weights, capacity allocation, convergence mechanism) must be clearly marked 
as experimental or derivative, and must not be represented as the canonical 
Free Association protocol without passing the reference conformance tests.

**Example required notice for modified versions:**
"This is a modified version of Free Association with experimental changes 
to [specify what changed]. It may not be compatible with the canonical protocol."

**Rationale:** Prevents fragmentation while allowing innovation. Modified 
versions are permitted under AGPL but must be clearly identified.

---

## 3. Interoperability Commitment (Section 7f)

Network services using this software should maintain interoperability with 
other Free Association implementations by:
- Using standard data formats as documented
- Enabling data export/import in canonical format
- Not creating artificial barriers to user data portability

**Rationale:** Ensures the coordination infrastructure remains open and 
prevents vendor lock-in.

These additional terms are specifically designed to:
